# DeepSeek Harness Lanyard

[English](README.md) | 简体中文

用手机打开 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的 Web 界面。

`dsh` 照常在电脑上跑，手机打开一个链接，界面就在那儿了：走自己家的网络，用配对令牌把关。同一个网络里的其他设备，碰不到你的会话，也碰不到这台机器。

这个插件只干这一件事。它不是网关，不是反向代理，也不能让你从外网连回自己的机器。

## 为什么非得装个插件

`dsh web` 默认只绑定 `127.0.0.1`，并且直接拒绝 `--host 0.0.0.0`。原因很实际：`/api` 会以 `dsh` 进程的身份执行命令，一旦在没有认证的情况下监听局域网，等于把远程执行代码的能力向整个网络敞开。代价是正当的用法也被一并挡住了，比如想窝在沙发上，用手机接着处理刚才的会话。

这个插件补上缺失的那层认证，让局域网监听变得安全。**不改动 Harness 源码**，以普通插件包的形式安装。

## 安装

```sh
dsh plugin --profile web add @koalafacts/deepseek-harness-lanyard
```

```sh
export DSH_PAIRING_TOKEN="$(node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))")"
dsh --profile web --host 0.0.0.0 --pairing-token-env DSH_PAIRING_TOKEN
```

启动时会打印配对链接，以及它对应的二维码：

```
lanyard: pair a device by opening https://192.168.1.5:3080/#auth=<token> once
lanyard: or scan this with the phone
```

### 命令行参数

| 参数 | |
|---|---|
| `--host 0.0.0.0` | 对局域网提供服务，必须同时给出配对令牌 |
| `--pairing-token-env <name>` | 存放令牌的凭据名（至少 16 位，取值为 `A-Za-z0-9_-`） |
| `--keep-awake` | 阻止主机休眠，免得手机用到一半被断开 |
| `--port`、`--no-open`、`--trusted-host` | 与上游行为一致 |

配置里写的是令牌的**引用名**，不是令牌本身。凡是会回显配置的地方（`dsh --dump-config`、崩溃转储等）都拿不到它；真正的取值放在环境变量、凭据存储或 `.env` 里。

## 手机这边

拿手机对着终端里的二维码扫一下，配对就算完成了。令牌是二十几个随机字符，没人应该拿手机键盘去敲它。（链接也一并打印出来了，想发给自己也行。）

扫完之后，页面会把令牌存下来，同时从地址栏里抹掉，之后每次访问都自动带上，直接输 `https://192.168.1.5:3080` 就能进。想用起来更像个 App，可以添加到主屏幕。

有三件事需要心里有数：

- **两台设备得在同一个网络里。** 链接用的是电脑的局域网地址，中间没有任何中转，数据也不出这个网络。
- **证书告警是正常的。** 证书是自签的，手机第一次会让你确认信任。真正保护这条连接的是令牌，不是证书。
- **换了网络就得换链接。** 电脑的局域网地址变了，重新打开启动时打印的那一条即可。

## 配对之后，手机能碰到什么

配对只能证明设备的身份，不能证明操作的人就坐在这台机器前面。所以手机拿到的是会话层面的能力：对话、命令、目标（goals）；凡是会改动这套安装本身的操作，仍然只能在本机进行。

- **只允许本机访问的部分**：设置、凭据、Agent 预设、系统原生对话框、模型发现，以及所有没有被明确归类过的 Gateway 命名空间。
- **令牌不会出现在请求里**。`#auth=…` 属于 URL 的 fragment，浏览器根本不会把这一段发出去，所以它既不会落进服务端日志，也不会经过任何代理。
- **TLS 在进程内解密**，客户端的真实地址因此得以保留。如果换成端口转发，所有请求看上去都来自本机，整套准入判断就形同虚设。
- **界面自身的静态文件不受令牌保护**。令牌是随页面一起送到浏览器的，页面没取回来就谈不上出示令牌，所以打包后的 HTML、JavaScript 和 CSS，同一网络里的任何设备都取得到。这些文件不含任何密钥，source map 也照旧被挡在外面。页面跑起来之后发出的每个请求，仍然要过令牌这一关。

## 已知限制

- **只有一个共享密钥，而且无法吊销**。要轮换就得改凭据再重启，也没办法单独把某一台设备踢掉。
- **隧道等同于本机**。用 `adb reverse` 或 `ssh -R` 打通之后，手机在服务端看来就是本机连接，既跳过令牌，也能碰到配置类接口。开这种隧道，相当于把键盘直接交给对方。
- **页面脚本读得到令牌**。这是没办法的事：令牌本来就由浏览器端保存和出示。
- **和所继承的 Web 服务器版本绑定**。将来某个版本的 `@deepseek-ai/dsh-host-webserver` 有可能让它失效；真出了问题会直接报错退出，不会悄悄退回明文。

## 配置

正常情况下一项都不用改。默认配置是安全的，没列出来的一律拒绝。有两项值得知道：`pairedNamespaces` 决定配对过的手机能碰到哪些东西，没写进去的一律只允许本机，所以这个范围只会被有意放宽；`fallbackAdmission` 决定界面自身的静态文件怎么发，默认照发，否则刚配对的手机连页面都打不开。完整字段和覆盖方式见 [AGENTS.md](AGENTS.md)。
