# DeepSeek Harness Lanyard

[English](README.md) | 简体中文

用手机打开 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的 Web 界面。

`dsh` 照常在电脑上跑，手机扫一下二维码，界面就在那儿了：走自己家的网络，全程 TLS 加密。同一个网络里的其他设备，碰不到你的会话，也碰不到这台机器。

这个插件只干这一件事。它不是网关，不是反向代理，也不能让你从外网连回自己的机器。

## 为什么非得装个插件

`dsh web` 默认只绑定 `127.0.0.1`，并且直接拒绝 `--host 0.0.0.0`。原因很实际：`/api` 会以 `dsh` 进程的身份执行命令。从 0.1.2 起，dsh 自己就会给每个浏览器做认证——启动行里那个带 `?token=` 的链接就是用来登录的——但它依然不肯对局域网提供服务：走的是明文 HTTP，而且只要浏览器登录过，就把它当成坐在键盘前的那个人。

这个插件解除这道限制，并补上局域网监听仍然缺的东西：TLS；在网络设备能碰到的每一条路由前面，都先过一遍 dsh 自己的会话校验；配置类接口仍然只留在本机。它自己不另设任何登录。**不改动 Harness 源码**，以普通插件包的形式安装。

## 安装

```sh
dsh plugin --profile web add @koalafacts/deepseek-harness-lanyard
```

```sh
dsh --profile web --host 0.0.0.0
```

启动时会打印配对链接，以及它对应的二维码：

```
lanyard: serving your network over TLS on port 3080 — the LAN address on the dsh web line is not reachable from other devices
lanyard: pair a device by opening https://192.168.1.5:3080/?token=<launch token> once
lanyard: or scan this with the phone
```

### 命令行参数

| 参数 | |
|---|---|
| `--host 0.0.0.0` | 通过 TLS 对局域网提供服务，并打印配对链接 |
| `--keep-awake` | 阻止主机休眠，免得手机用到一半被断开 |
| `--port`、`--no-open`、`--trusted-host` | 与上游行为一致 |

需要 dsh 0.1.2 或更高版本，这是第一个自带浏览器登录的版本。在更早的版本上，它会在启动时直接报错，并拒绝网络上的所有设备，而不是在没有登录的情况下对局域网敞开。

## 手机这边

拿手机对着终端里的二维码扫一下，配对就算完成了。链接里带着 dsh 的启动令牌，43 个随机字符，没人应该拿手机键盘去敲它。（链接也一并打印出来了，想发给自己也行。）

打开它，手机就登录了：dsh 用令牌换出一个会话 Cookie，再重定向回不带令牌的地址，令牌随即从地址栏消失。之后直接输 `https://192.168.1.5:3080` 就能进，重启 dsh 也不受影响，直到会话过期为止——默认 30 天。想用起来更像个 App，可以添加到主屏幕。

有三件事需要心里有数：

- **两台设备得在同一个网络里。** 链接用的是电脑的局域网地址，中间没有任何中转，数据也不出这个网络。
- **证书告警是正常的。** 证书是自签的，手机第一次会让你确认信任。在你确认之前什么都不会发出去，链接里的令牌也不会。
- **换了网络就得换链接。** 会话绑定在打开它时所用的地址上。电脑的局域网地址变了，扫一下启动时新打印的那个即可。

## 配对之后，手机能碰到什么

配对只能证明设备登录过，不能证明操作的人就坐在这台机器前面。所以手机拿到的是会话层面的能力：对话、工作区及其中的文件、后台任务、终端，以及回应 Agent 的审批请求和提问；凡是会改动这套安装本身的操作，仍然只能在本机进行。

- **只允许本机访问的部分**：设置、凭据、账号、模型服务商、安装或查看插件、任何会在这台机器屏幕上打开东西的操作，以及所有没有被明确归类过的 Gateway 命名空间。
- **每一条路由前面都会校验 dsh 的会话**，不只是 dsh 自己把关的那些。某条路由的所有者忘了做校验，网络上的设备也照样进不去。
- **TLS 在进程内解密**，客户端的真实地址因此得以保留。如果换成端口转发，所有请求看上去都来自本机，会话校验和配置类接口的限制就都形同虚设。
- **界面自身的静态文件不受会话保护**。配对请求和这些文件走的是同一条路由，那时手机还没有会话；这些文件不含任何密钥，source map 也照旧被挡在外面。页面本身由 dsh 负责登录校验，页面跑起来之后发出的每个请求都需要会话。

## 已知限制

- **要让一台设备退出登录，只能让所有设备一起退出**。所有会话都由同一个密钥签发，也就是 dsh 凭据存储里 `client-connection` 的 browser-session 记录；替换它是唯一的吊销方式。
- **隧道等同于本机**。用 `adb reverse` 或 `ssh -R` 打通之后，手机在服务端看来就是本机连接：它仍然需要 dsh 的会话，但能碰到配置类接口。开这种隧道，相当于把键盘直接交给对方。
- **流式调用不逐个归类**。它们共用一条 WebSocket，只能整体放行或拒绝，所以配对过的手机有可能订阅到某个本应被拒绝的命名空间里的流——目前只有只读的账号状态。所有写操作都走 HTTP，每个调用都会单独归类。
- **和所继承的 Web 服务器、所依赖的登录机制绑定**。将来某个版本的 dsh 有可能让它失效；真出了问题会直接报错，不会悄悄退回明文，也不会放未登录的设备进来。

## 配置

正常情况下一项都不用改。默认配置是安全的，没列出来的一律拒绝。有两项值得知道：`pairedNamespaces` 决定配对过的手机能碰到哪些东西，没写进去的一律只允许本机，所以这个范围只会被有意放宽；`fallbackAdmission` 决定界面自身的静态文件怎么发，默认照发——改成 `gated` 的话，新设备就根本无法配对了。完整字段和覆盖方式见 [AGENTS.md](AGENTS.md)。
